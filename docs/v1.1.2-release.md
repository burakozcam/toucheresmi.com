# v1.1.2 — 9 Kasım 2026

Bu çalışma yerel geliştirme ve doğrulamadır. Canlıya dağıtım, canlı veritabanına migration, seed, GitHub push veya kullanıcı kayıtlarına müdahale yapılmadı. Karşılaştırma tabanı: `981aa87` (v1.1.1).

## 1. Düzeltilen hatalar ve kullanım

- API artık Excel okuyucusunu `@optik/web/public/vendor/xlsx.full.min.js` yolundan almıyor. Kendi üretim bağımlılığı olan SheetJS kullanılıyor. F/O parser modülleri API içinde bağımsız çalışıyor; Web aynı modüllere ince bir adaptörle erişiyor.
- **Cevap Anahtarları** tek yönetim noktası: liste, yeni kayıt, dosya/bilgi güncelleme, soru/kazanım düzenleme ve toplu dosya ekleme. Önceki sürümde sınava bağlanmamış anahtarlar aynı bölümde düzenlenip mevcut sınava bağlanabiliyor.
- Kaynak formatı isteğe bağlı **Otomatik / Genel**, **F**, **O**. Arayüz ve uygulamanın hata metinlerinde dış sistemlerin tam adları kaldırıldı. Kullanıcının yüklediği belgenin kendi içeriği ve dosya adı değiştirilmez.
- Gerçek örnek `.xls` ve `.xlsx` dosyalarıyla F/O ayrıştırma korunuyor. Genel CSV/TSV ve okunabilir sütun başlıkları olan tablo PDF’si destekleniyor. Taranmış PDF için açık kaynak Excel/CSV veya OCR yönlendirmesi veriliyor; cevap/kitapçık tahmini yapılmıyor.
- Doğru cevap içeren kazanımdan ayrıca cevap dosyası gerektirmeden anahtar oluşuyor. Tam tablo düzenlenip açıkça onaylanıyor. Onaylanan veriden gömülü Türkçe fontlu, A/B/C/D kitapçık sırasını izleyen indirilebilir PDF üretiliyor. Kaynak dosya ve satır değerleri korunuyor.
- Ana sayfa ve ölçme sistemi yayın seçenekleri bağımsız; varsayılanı kapalı. Aynı sınav kaydı kullanılıyor. Soru düzenlemesi bağlı sınav için PDF’yi yeniliyor; eski sonuç anlık kopyalarını değiştirmiyor. Ana sayfa en yeni oluşturulmuş PDF’yi seçiyor.
- FMT Yönetimi: gerçek alan tanımlarını okuma, alan/ders/kapasite tablosu, belirsiz eşleştirmeleri işaretleme, düzeltme, isimlendirme, çoklu yükleme, toplu kayıt. Teknik yerleşim ve JSON içe aktarma Gelişmiş Düzenleme altında. İsim ve aynı içerik/yerleşim için mükerrer kontrolü var.
- FMT tanım sırası, koordinatlar ve kapasiteden öneri üretiliyor; dosya adına göre kesin eşleştirme yapılmıyor. Kaydetmek için gerçek TXT testi ve okuyucu uyumluluk beyanı gerekiyor. Sunucu doğrulama kanıtını kullanıcıya, içeriğe, yerleşime, kodlamaya ve okuyucu bilgisine bağlıyor.
- 7108/8050 özgün örnek FMT indirmeleri ve kayıtlı FMT indirmeleri mevcut. Yüklenen özgün baytlar korunuyor. Özgün dosyası bulunmayan kayıtta JSON, FMT olarak sunulmuyor; ayrı `.layout.json` indirme ve özgün FMT ile içe aktarma yolu gösteriliyor.
- 13 süre seçeneğiyle paylaşım: 5/10/30 dakika, 1/3/5/12 saat, 1/2/3/5 gün, 1 hafta, 1 takvim ayı. 256 bit rastgele anahtar; DB’de yalnızca SHA-256 özeti. Anahtar URL fragmentinde taşınıyor, indirme isteğinin gövdesinde sunucuya gönderiliyor. Tek FMT kapsamı, sunucuda süre/iptal/etkinlik kontrolü. Panel erişimi sağlamıyor. Link ve WhatsApp açıklaması kopyalanabiliyor; mesaj kendiliğinden gönderilmiyor.
- Paylaşım iptalinin boş `204` yanıtını JSON sanarak hata gösteren istemci düzeltildi.
- Sınav Yükle yayınevlerini bağımsız veritabanı sorgusuyla alıyor; sınıf, hazır sınav, etkin FMT, kurum ve TXT seçiliyor. Hazır sınav yoksa nedenini açıklıyor. Önizleme ve onay sonrası mevcut sonuç/karne altyapısı kullanılıyor.
- TXT dönüştürmeye varsayılan kodlama ve satır sonlarını öneren açıklama eklendi.
- Yönetim alanı genişletildi; cevap önizlemesindeki iç dikey kaydırma kaldırıldı, geniş tablolar yatay kaydırılabilir. Mevcut yavaş login gradienti ve reduced-motion davranışı korundu ve kontrol edildi. Alt bilgi v1.1.2, altın parıltısı ve silik 9 Kasım 2026 tarihi gösteriyor.

## 6. Veridyen / cPanel dağıtım sırası — henüz uygulanmadı

Bu adımlar yalnızca canlıya geçiş onayından sonra uygulanır. cPanel hesabının gerçek uygulama kökü ve mevcut Web başlangıç yöntemi bu oturumda görülmedi; aşağıdaki `RELEASE_DIR` ve `UPLOAD_DIR` değerlerini paneldeki gerçek yollarla doldurun. Dizinleri tahmin ederek değiştirmeyin.

1. cPanel’de mevcut API/Web uygulama köklerini, startup dosyalarını, Node sürümünü, ortam değişkenlerini ve önceki çalışan commit’i kaydedin. Neon yedeği/snapshot ve **mevcut yükleme klasörünün** yedeğini alın. Yedek geri yükleme yolunu doğrulayın. JWT_SECRET’i değiştirmeyin.
2. Yeni release’i ayrı dizine alın. Çalışan dizinin üstüne eksik dosyalar kopyalamayın. Node 20+ ortamını etkinleştirin. `DATABASE_URL`, `JWT_SECRET`, `WEB_ORIGIN=https://kurumsalsinav.com` ve kalıcı **mutlak** `STORAGE_DIR` değerlerini mevcut güvenli ortamdan sağlayın. `.env` içeriğini terminal çıktısına dökmeyin. Testte kullanılan `/tmp` veya sahte DB URL’sini canlıya taşımayın.
3. Monorepo kökünde aşağıdaki hazırlığı çalıştırın. Bu aşamada migration yoktur:

```sh
cd "$RELEASE_DIR"
node --version
npm ci
npm run db:generate
npm test
NEXT_PUBLIC_API_URL=https://api.kurumsalsinav.com npm run build
npx prisma validate --schema apps/api/prisma/schema.prisma
npx prisma migrate status --schema apps/api/prisma/schema.prisma
```

4. `migrate status` çıktısını inceleyin. Repo README’sinde geçmişte `20261106000000_publisher_answer_key_support` migration’ının başarısız olduğuna dair not var. Canlı durumunu bu oturumda doğrulamadık. Başarısız migration varsa burada durun; `_prisma_migrations` ve gerçek tablo/enum durumunu salt okunur kontrol etmeden `resolve`, `reset`, `db push`, tablo silme veya migration kaydı silme çalıştırmayın. Bekleyen migration’ların tamamını, yalnızca yeni dosyayı değil, gözden geçirin.
5. Aynı migration dizisini önce üretim kopyası olan staging DB’de uygulayın. F/O, yayın seçenekleri, PDF indirme, FMT paylaşım/iptal, 7108 TXT sonucu ve manuel değerlendirmeyi staging’de kontrol edin. Bu adım gerçek PostgreSQL üzerinde eksik kalan doğrulamayı tamamlar.
6. Yedek, staging ve bekleyen migration’lar onaylandıktan sonra bakım aralığında, doğru canlı bağlantı bağlamında yalnızca:

```sh
npm run db:migrate:deploy
```

`db:migrate` (dev), `prisma migrate reset`, `db push --accept-data-loss` ve `db:seed` çalıştırmayın.

7. API cPanel/Passenger uygulama kökü: `$RELEASE_DIR/apps/api`; startup dosyası: **`passenger.cjs`**; production ortamı. Bu dosya gerçek Passenger’da `listen('passenger')` kullanır. Standalone süreç yönetimi kullanılıyorsa mevcut `npm run start -w @optik/api` desteklenmeye devam eder; iki yöntemi aynı uygulamada birlikte başlatmayın.
8. API runtime’da `dist/src`, **`dist/lib`**, **`dist/assets`**, üretim bağımlılıkları ve üretilmiş Prisma istemcisi bulunmalı. Yalnız `dist/src` yüklemek hatayı yeniden üretir. Monorepo dağıtımında kökteki `node_modules` erişilebilir olmalı. Ayrı API paketi yapılacaksa API package.json + dist + passenger.cjs + şema ile üretim bağımlılıklarını kurun, Prisma istemcisini hedef Linux ortamında üretin; yalnız Web vendor dosyasını kopyalama yoluna dönmeyin.
9. Web’i mevcut çalışan SSR startup yöntemiyle yeni `apps/web/.next` derlemesine yönlendirin; `public` varlıkları ve gereken workspace kaynakları korunmalı. Bu sürüm Web’in mevcut cPanel startup yöntemini değiştirmiyor. `/fmt-paylasim/[id]` dinamik SSR gerektirir; statik HTML export yeterli değildir. Web için `API_INTERNAL_URL` tanımlıysa yeni API’ye erişebilen güvenilir iç URL kullanın; yoksa `NEXT_PUBLIC_API_URL` değerine düşer. **Testteki `127.0.0.1:4102` değerini canlıya taşımayın.**
10. cPanel’in Restart işlemiyle önce API, sonra Web’i yeniden başlatın. Application Manager kullanılıyorsa ilgili uygulama kökünde `tmp/restart.txt` yöntemini sağlayıcının yapılandırmasına göre kullanabilirsiniz. Kullanıcı yüklemelerinin sahibi/okuma-yazma izinlerini kontrol edin; `chmod 777` kullanmayın.
11. `https://api.kurumsalsinav.com/api/health` için `200` kontrol edin. Loglarda eksik modül/Prisma sütun hatası olmamalı. Test kurumuyla F ve O içe aktarma, PDF indirme, yalnız ana sayfa / yalnız değerlendirme / ikisi, 7108/8050 indirme, kısa paylaşım+iptal ve TXT→karne akışını canlı kontrol edin. Son kullanıcı verileriyle toplu deneme yapmayın.
12. Sorun olursa API/Web’i önceki çalışan release’e döndürün; bu eklemeli migration’ın sütun/tablosunu aceleyle silmeyin. Aynı kalıcı STORAGE_DIR’i koruyun. Veritabanı yedeğine dönüş, yeni kayıtları etkileyebileceğinden ayrı karar gerektirir.
